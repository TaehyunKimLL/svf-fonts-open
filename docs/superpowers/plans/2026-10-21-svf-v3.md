# SVF v3 (aligned ink-box glyph records, per-target layout profiles, v3 only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace SVFN v2 with SVFN v3 (48-byte header, layout bytes, glyph offset table, ink-box glyph records padded to
the record unit) in every reader and writer of svf-fonts, ScummVM and the harness, convert all 153 shipped faces with a
pixel-identity proof against the last v2 build, rebuild the packs, then drop v2.

**Architecture:** One shared Python packer and parser in `tools/jamoset.py` (`pack_svfn`, `parse_svfn`, named
`PROFILES`) is the reference; `tools/svf2to3.py` converts v2 to v3 and re-lays a v3 face into another profile. The C
library expands a record into the caller's cell, so nothing after the cell (blits, cache, scaling, marks, dy) changes;
it reads v2 and v3 for one transitional stretch (Tasks 4-5), so every task stays green, and the v2 path is deleted in
the same task that regenerates `svf/` after the identity proof (Task 6). Ports convert faces to their own profile at
build time (`mkface.py --profile`); `svf/` holds the `default` profile only. ScummVM and the harness follow in their own
repositories (Tasks 10-12), the engine becoming v3-only in the same commit that pins the v3 faces.

**Tech Stack:** C99 (`-std=c99 -Wall -Wextra -Werror`), make, POSIX sh, Python 3 unittest; the cross toolchains and
emulators of `c/cross/install-toolchains.sh` and `c/bench/install-emulators.sh` (arm-none-eabi-gcc 15.2.1,
riscv32-esp-elf-gcc 16.1.0, riscv32-pico-elf-gcc 16.1.0, Espressif QEMU 9.2.2, qemu-system-arm 8.2.2, rp2040js 1.4.0,
rp2350js af0114c + patch, simavr 1.8, DOSBox-X, DJGPP gcc 12.2.0, emcc 6.0.13, node v24.13.0, pico-sdk 2.3.1); clang
with libFuzzer for Task 8; ScummVM's CxxTest suite through `tools/korean/engine_gate.sh`.

**Spec:** `docs/superpowers/specs/2026-10-21-svf-v3-design.md` (commit 55d29b9, approved by the user 2026-10-21, card
t_227d5486). Read it fully before any task: the format, the profiles, the supported sets, the test plan and the owner
decisions are argued there and not repeated here.

## Global Constraints

- **v3 only at the end.** v2 was never distributed: after Task 6 no reader in svf-fonts reads v2, after Task 10 none in
  ScummVM, after Task 12 none in the harness. The only v2 parser left is `_parse_v2` inside `tools/svf2to3.py`. v1 and
  v2 are refused cleanly: C `SVF_E_VERSION`, Python `ValueError("SVFN version 2: convert with tools/svf2to3.py")`
  (version 1: the same text with 1), ScummVM `kMinVersion = kMaxVersion = 3` (a new constant) with its existing
  warning. Known casualty, accepted by the user (F1): the v1 hi-res faces of the Dig and FT packs stop loading until
  the follow-up card of Task 9 converts them.
- **Pixels never change.** A face's pixels are the same in every profile and before/after conversion: the bench
  checksums (`c/bench/sums.py`, `sums.inc.sh`) are not edited for any existing case, every runner reports `ok`, the ten
  `c/ports/dos/shots/*.png` and the `run-screens.sh` references are unchanged.
- Magic `SVFN`; version u16 at 4 = 3; header 48 bytes; header bytes 0..35 keep their v2 meaning except 9 and 10 (layout
  bytes) and 11 (reserved, written 0, ignored); 36 u32 JSET offset, 40 u32 JSET size, 44 u32 glyph offset table offset.
  Layout byte 9: bits 0-2 REC, 3-5 ROW, 6-7 zero; byte 10: bits 0-2 TAB, bit 3 OFF (0 = u16 in units of 2^REC, 1 = u32
  bytes), 4-7 zero; REC, ROW, TAB <= 6, ROW <= REC.
- Record: `x0` (bytes), `y0`, `wb` (bytes), `h`; then the phase bytes, `h` rows of `rp = (wb + 2^ROW - 1) & ~(2^ROW - 1)`
  bytes, padding to the next multiple of 2^REC. Phase = `(y0 * pitch) & 3` only when `REC >= 2`, `ROW == 0` and
  `wb == pitch`, else 0. Blank = `wb == 0` or `h == 0`. `x0 + wb <= pitch`, `y0 + h <= cell_h`.
- Profiles (writer presets, names exact): `mcu-strict` REC 4 / ROW 1 / TAB 4 bytes, x-boxed, u16 (u32 when the data
  passes `65535 << REC`); `default` 4/1/4, x-boxed, u32; `dos` and `wasm` 1/1/1, x-boxed, u16 (u32 past 64 KB); `full`
  4/1/4, full cells, u32; `simd16` 16/1/16, x-boxed, u32. `--profile` defaults to `default` in every writer.
- Error codes: `SVF_E_LAYOUT` is appended to `svf_err` after `SVF_E_ARG` (value 8). Layout-byte faults, a unit outside
  the build's set, an unaligned offset, entry or size, and an inconsistent offset table are `SVF_E_LAYOUT`; a table
  outside the file and a record that breaks its box or length are `SVF_E_RANGE`; check order is magic, version, layout
  bytes, supported set, bpp, box, table ranges, alignment masks, offset table, records.
- C library rules stay: C99, only `<stdint.h>`, `<stddef.h>`, `<string.h>`; no allocation (`c/check.sh` no-malloc); no
  static data but `static const`; `sizeof(svf_face)` <= 64 on 32 bits, <= 96 on the host (`TestFaceSize`);
  `svf_chain_scratch_bytes` and the cell-sized scratch rule unchanged; the signature and contract of
  `svf__merge(const svf_face *f, uint8_t *dst, const uint8_t *src, uint16_t n)` unchanged and `c/tests/test_kernels.c`
  unchanged and green (the C speedups build on both).
- Cortex-M0+ P1/P2 text <= 8192 B after every library task (`c/cross/build-all.sh`), the number in the commit message.
  AVR `run-avr.sh` fits 32,256 B of flash. A task that moves a port image size updates, in the same commit, both

## Review Focus

1. A streamed face **without a cache** whose record is longer than the cell (every `full`-profile glyph, a full-width
   box with phase): the reader may use only the cell's `svf_cell_bytes` bytes (and the second half for a compose) and
   must still give the mapped result — Task 4 `test_stream_records_longer_than_cell` (`full` profile, `--stream`, all
   glyphs and syllables equal to mapped, ASan clean, reads per such glyph 2: the header, then all rows in one read,
   F14; one read per row only when `h * rp > svf_cell_bytes`, which no named profile produces).
2. A record whose 4-byte header or one of whose rows **straddles two cache blocks** (64-byte blocks, `dos` profile with
   byte-tight records at every offset) — Task 4 `test_stream_cache_records_straddle_blocks` (`--stream=1:64`, every
   profile, equal to mapped).
3. A mapped face handed to the library at an **address that is not 4-aligned** (a port that embeds without `aligned`,
   a file read into `malloc(len) + 1`): v3 offsets are aligned relative to the file start only; nothing may assume the
   base is aligned — Task 4 `test_mapped_face_at_odd_address` (svfdump `--face-offset=1..3`, all profiles, equal dumps).
4. **Edge cells**: a blank glyph, ink touching all four cell edges, a single pixel in the last column of a cell whose
   width is not a multiple of 8 (padding bits) and of a 2 bpp cell, an 8 bpp cell of 255 everywhere — Task 2
   `test_record_edge_cells` (encode/decode round trip in every profile, box exactly as spec'd).
5. **Offset width at its boundary**: glyph data of exactly `65535 << REC` bytes stays u16, one more unit switches to u32
   (`mcu-strict` at 256 KB, `dos` at 64 KB), and the u16 reader scales entries by `2^REC` — Task 2
   `test_offset_width_boundary` and Task 4 `test_u16_offsets_at_boundary` (the C reader on both files).

Note for reviewers: the spec's "the streamed open must give the mapped open's result" applies to header and table cases;
a record fault refuses a mapped face at open but a streamed face only when that glyph is read (spec "Glyph record",
design call 11). Task 4's hostile tests assert exactly that split.

### Task 2: The v3 format in `jamoset.py`: profiles, records, the shared packer, the parser

**Files:**
- Modify: `tools/jamoset.py` (constants at 46-57, `Svfn`/`parse_svfn`/`write_svfn` at 569-640)
- Test: `tools/test_jamoset.py` (new class `TestSvfn3`)

**Interfaces:**
- Produces (all in `tools/jamoset.py`):
  - `VERSION = 3`, `HEADER3 = "<4sHHBBBBHBBBbbBIIIIIII"` (48 bytes, field order of the spec header),
    `HEADER3_SIZE = 48`.
  - `Profile = collections.namedtuple("Profile", "rec row tab box off")`: `rec`, `row`, `tab` log2 0..6, `box` in
    `{"x", "y", "full"}`, `off` in `{"u16", "u32", "auto"}` (`auto`: u16 when the data size is at most `65535 << rec`).
  - `PROFILES`: `mcu-strict` `Profile(2, 0, 2, "x", "auto")`, `default` `(2, 0, 2, "x", "u32")`, `dos` and `wasm`
    `(0, 0, 0, "x", "auto")`, `full` `(2, 0, 2, "full", "u32")`, `simd16` `(4, 0, 4, "x", "u32")`.
  - `profile_of(p, box=None) -> Profile`: a name, a `Profile`, or a units string `"R,W,T,O"` (log2 values, O `16` or
    `32`, box `x`) — the last for tests and `--units`; `ValueError` on ROW > REC or a value past 6.
  - `cell_box(cell: bytes, pitch: int, cell_h: int, box: str) -> tuple` `(x0, y0, wb, h)`: x the byte span of the
    non-zero bytes, y the rows holding one; `(0, 0, 0, 0)` for a blank cell in every box policy (spec "Blank glyph",
    F18); for a non-blank cell `full` gives `(0, 0, pitch, cell_h)`, `y` gives `(0, y0, pitch, h)`.
  - `encode_record(cell, pitch, cell_h, box, rec, row) -> bytes` (header, phase, rows of `rp`, padding to `2^rec`).
  - `decode_record(buf: bytes, pitch, cell_h, rec, row) -> bytes`: the full cell; `ValueError` on `x0 + wb > pitch`,
    `y0 + h > cell_h`, rows past `len(buf)`, `len(buf) < 4`.
  - `pack_svfn(cell_w, cell_h, ascent, bpp, flags, cells, cmap, metrics=None, jset=None, dy_range=(0, 0),
    profile="default") -> bytes`: `cells` in glyph index order; `cmap` `[(cp, index)]` as written; `metrics`
    `[(advance, bearing_x, ink_w, dy)]` by index or None (flag bit 0 from it); `jset` bytes or None (flag bit 1 from
    it); other flag bits from `flags`. File order: header, cmap, JSET, metrics, offset table, glyph data, each start
    rounded up to `2^tab` (glyph data to `2^max(tab, rec)`), padding bytes 0. The only header packer in tools/.
  - `parse_svfn(data) -> Svfn`, v3 (this task also keeps the v2 branch; Task 6 removes it): attributes `version`,
    `flags`, `bpp`, `cell_w`, `cell_h`, `ascent`, `count`, `dy_min`, `dy_max`, `glyphs {cp: full cell}` (last cmap entry
    wins), `metrics {cp: (adv, bx, iw)}`, `dy {cp: dy}` (non-zero only), `jset` (bytes or None), `metrics_ok` (False
    when flags name a metrics table outside the file or inside the header: dropped, as the C library does),
    `layout` (`(rec, row, tab, off32)` for v3, None for v2). Every check of the spec's "Layout bytes", "Tables" and
    "Glyph record" raises `ValueError` naming the rule; a JSET with a bad size or size 0 with the flag gives
    `jset = None`.
  - `write_svfn(cell_w, cell_h, ascent, glyphs, jset, extra_flags=0, shadow=SHADOW_NONE, codepage=CODEPAGE, bpp=1,
    dy=None, profile=None)`: `profile=None` writes v2 exactly as today (transitional, removed in Task 5); a profile
    writes v3 through `pack_svfn` with `jset or None`.
  - `relayout(data: bytes, profile, box=None) -> bytes`: `parse_svfn` then `pack_svfn`, glyphs in code point order,
    effective metrics (cell advance when not `metrics_ok`) and effective dy (0 outside a valid range).

- Open: after the version (2 → today's path, `layout |= SVF__LAYOUT_V2`; 3 → v3), the layout-byte checks, then the
  supported set, then the v2 checks of bpp and box, then every table inside the file and at or after byte 48, then the
  alignment masks, then the offset table (`glyphs + 1` entries, non-decreasing, each a multiple of `2^REC` in bytes,

  offset 36 / size 40 (no inference).
- Streamed open loads the offset table into the tables buffer after the JSET (`svf_stream_tables_size` grows by
  `(glyphs + 1) * (2 or 4)`; refused `SVF_E_NOMEM` where that does not fit `size_t`); records are checked when read.
- Streamed read of record `g` without a cache: when its length is at most `svf_cell_bytes`, one read into the end of
  the buffer (the cell for a copy, the scratch half for a merge), then the rows are moved to their places in order
  `r = 0..h-1` (each row's source lies at or after its destination; check the first and last row, the offset is linear
  in `r`, and fall back to the next rule otherwise) and the gaps cleared. When the record is longer than the cell but
  its rows (`h * rp` bytes) fit `svf_cell_bytes` — always so with ROW 0, i.e. every named profile, including every
  `full` glyph and a full-width full-height `dos` glyph — one read of the 4-byte header, then one read of the `h * rp`
  row bytes into the end of the buffer, then the same in-place row move: 2 reads (spec design call 6 and "Reading a
  glyph", F14). Only when `h * rp > svf_cell_bytes` (ROW > 0) one read of `wb` bytes per row, straight to its place.
  With a cache: header and rows through `svf__stream_bytes`.
  The cache's block cut is the end of the glyph data (`data_off + data_size`).

## What the C speedups (Tasks 6-10, re-planned on v3) consume

- **Aligned sources.** In `mcu-strict` and `default` every record starts at a multiple of 4 from the file start, and
  `mkface.py` aligns the embedded array to 4 (Task 7), so a mapped record is 4-aligned in memory on every port. A
  full-width record's rows start at `phase` so that `src` (record rows) and `dst` (`cell + y0 * pitch`) are equal
  modulo 4: the word loop of `svf__merge` runs after a byte head with native loads on both sides when the caller's
  cell is 4-aligned (the speedups plan's F16). x-boxed narrower records are row-wise runs of `wb` bytes (1-5 bytes on the MCU faces):
  the byte loop serves them; the speedups measure whether a row loop is worth it.
- **One entry point.** `svf__expand` (Task 4) is the only caller of `svf__merge` for glyph data and calls it once per
  contiguous run; `svf__merge`'s signature and `test_kernels.c` are unchanged, so Task 6's word loop and its net apply
  as written, with the alignment test now hitting aligned sources on M0+/Hazard3/C3.
- **Fixed units.** The one-pair `SVF_LAYOUTS` build (M0+ P1/P2, AVR) folds REC/ROW/TAB to constants; the speedups may
  rely on `SVF__REC(f) == 2` there at compile time.

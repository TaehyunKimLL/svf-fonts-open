# SVF Maker v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A stdlib HTTP server under `maker/` that takes uploaded fonts, lists what it found, runs the repository's own
tools (`mkfont.py`, `jamoset.py`, `jamovec.py`, `bdfface.py`) as background jobs and hands back a zip that unpacks into
`svf/`, with the TSV lines and a build log; no AI, the owner the only user.

**Architecture:** Flat modules in `maker/`: `detect.py` (pure functions: format, metadata, coverage, licence search),
`presets.py` + `routes.py` (source kind -> exact tool argv), `naming.py`, `settings.py` (defaults, validation, the step
list), `quality.py` (facts and quality read back from a produced face), `zipout.py` (zip, `.lines`, build log),
`preview.py` (PNGs), `archive.py` (upload guards), `jobs.py` (job directory store, FIFO worker thread, subprocess runner),
`server.py` (`ThreadingHTTPServer`, JSON API, static page), `static/` (one ES module page). `job.json` is the only
state; the page restores from it. Every conversion is a subprocess with an argument list, never an import of a tool.

**Tech Stack:** Python 3.12.3 at `/usr/bin/python3`, standard library plus Pillow 10.2.0 and fontTools 4.66.1 (already
installed; nothing else is installed). Plain ES2022 in the page, no framework. `unittest`. The UI smoke test uses node
and `playwright-core` from `web/test` when present.

**Spec:** `docs/superpowers/specs/2026-10-21-svf-maker-design.md` at `2046105`. Read it first: every rule below is
argued there. Tool facts the plan relies on (verified 2026-10-21): `tools/mkfont.py` (`NAMED_RANGES`, `cmap_has`,
`parse_ranges`, `collect_chars_from_files`), `tools/jamoset.py` (`parse_svfn`, `unpack`, `compose`, `LAYOUTS`,
`check_blank_slots`, `glyph_gint`, `PIECE_BASE`, `BLANK`, `FLAG_JAMO`, `FLAG_VARIABLE`), `tools/jamoaa.py`
(`OutlineFace`, `frame`, `direct_levels`, `outline_targets`, `unpack_levels`), `tools/jamovec.py` (`composite_parts`),
`tools/jamofit.py` (`quality_report`, `iou`), `tools/bdfface.py` (`read_bdf`, `read_hbf`), `tools/svfline.py`
(`Face`, `measure`, `layout`), `web/mkindex.py` (`read_licences`, `read_families`, `read_faces_tsv`).

## Global Constraints

- Python: `/usr/bin/python3` 3.12.3; imports limited to the standard library, `PIL` (10.2.0) and `fontTools` (4.66.1).
  `freetype`, `uharfbuzz`, `skia-pathops`, `flask`, `fastapi`, `aiohttp`, `python-multipart` are not installed and must
  not be imported or installed. No `pip install`, no `npm install` outside `web/test`.
- `maker/` holds flat modules: no `__init__.py`, no relative imports. Every entry point (`maker/server.py`,
  `maker/test/fixtures.py`, every `maker/test/test_*.py`) begins, before any other project import, with this bootstrap
  (test files use `os.path.dirname(os.path.dirname(...))` once more to reach `maker/`):

      import os, sys
      MAKER_DIR = os.path.dirname(os.path.abspath(__file__))
      REPO_DIR = os.path.dirname(MAKER_DIR)
      for _p in (MAKER_DIR, os.path.join(REPO_DIR, "tools")):
          if _p not in sys.path:
              sys.path.insert(0, _p)

  Library modules (`detect.py`, `routes.py`, ...) then `import jamoset`, `import svfline`, `import mkfont`,
  `import bdfface`, `import jamoaa`, `import jamovec`, `import jamofit` at top level and assume the path is set.
- Conversions never import a tool. Every tool run is
  `[sys.executable, "-P", os.path.join(tools_dir, "<tool>.py"), ...]` with absolute paths for every file argument
  (`-P`, not `-I`: `-P` keeps the script directory and the cwd off `sys.path` but keeps the user site, where fontTools
  4.66.1 is installed; `-I` would drop fontTools and break `jamovec.py`, the 2 bpp fit and `cmap_has`; the subprocess
  env carries no `PYTHON*` variable anyway),
  `cwd` = the step's work directory, `env = {"PATH": os.environ.get("PATH", "/usr/bin:/bin"), "HOME": os.environ.get("HOME", "/"), "LANG": "C.UTF-8"}`,
  never a shell. `tools_dir` is `<SVF_MAKER_REPO>/tools`.
- The maker never writes under `SVF_MAKER_REPO`. It writes only under `SVF_MAKER_DATA` (jobs) and into the zip.
- Environment: `SVF_MAKER_REPO` (default `<workdir>/svf-fonts`), `SVF_MAKER_DATA` (default `~/.local/share/svf-maker`),
  `SVF_MAKER_BIND` (default `100.78.108.85:8766`). Tests never use the defaults: they pass a temp data root and the
  checkout found from the test file's own path.
- Limits (verbatim from the spec): upload body 64 MB (`67108864`), job total 256 MB (`268435456`) and 2,000 files, path
  component 255 bytes, archive member 128 MB (`134217728`), archive total 512 MB (`536870912`) or 50 times the packed
  size, step timeout 600 s, job timeout 4 h (`14400`), tool output cap 4 MB (`4194304`), retention 20 jobs and 7 days,
  poll 2 s, `terminate` then `kill` after 5 s, job id `secrets.token_hex(6)`.
- Face names match `^[A-Z0-9]{1,8}\.SVF$`, text names `^[A-Z0-9]{1,8}\.TXT$`; destination folders match
  `^(dos|jamo-extra|games/[a-z0-9-]+|new/[a-z0-9-]+)$`; sizes are ints 6..96; bpp is 1 or 2; `range` is `"11172"`,
  `"2350"` or an upload-relative path of a list file.
- `mkfont.py` is always run with `--unicode` (v2 output); no fixed-width option exists on the precomposed route; 2 bpp
  is never offered for a bitmap or SVF source; `jamoset.py` 1 bpp fits always carry `--binarize threshold`, 2 bpp fits
  never carry `--binarize`.
- Sample text everywhere: `다람쥐 헌 쳇바퀴에 타고파 ABC xyz 0123`.
- API errors are JSON `{"error": "<message>"}` with status 400, 404, 409, 411, 413 or 500.
- Every zip entry has mtime `(1980, 1, 1, 0, 0, 0)`.
- Tests: `python3 -m unittest discover -s tools -p 'test_*.py'`, `python3 -m unittest discover -s maker/test -p 'test_*.py'`
  and `make -C c check` stay green after every task. `tools/test_tools_doc.py` must keep passing: nothing is added under
  `tools/` or `web/` except the Task 1 fix and the Task 15 README/docs edits.
- Commits: plain messages (`maker: ...`, `mkfont: ...`), no trailers, never `git add` anything under `.superpowers/`.
  Run `git status` before each commit and add only the task's files.

## Review Focus

1. A TTF whose `name` table is missing IDs 16/17 and 1/2, or holds only non-ASCII names: `read_name` must return
   non-empty family/style (the names as found when present, even all non-ASCII such as "나눔고딕"; the file stem with any
   trailing `.gz` removed, style `""`, only when the table has none) and `abbr()` a non-empty `[A-Z0-9]{1,5}` (`"FONT"` when the family
   has no ASCII letter or digit), or the suggested names are invalid and `run` is refused with no fix. `read_name`'s
   fallback is tested in Task 3, `abbr`'s in Task 6.
2. A second upload of the same `path` into the same job (the owner retries a browser upload): the file is overwritten,
   not duplicated, and `detect` lists it once. Test in Task 13.
3. A `PUT settings` carrying a font id or name key that `detect` never produced, or a `names` value with a lower-case
   or 9-character name: 400 with the key named, and `job.json` unchanged. Test in Task 7 (validation) and Task 13 (HTTP).
4. The service restarted while a job is `running` and its `work/` holds a half-written `.SVF`: `recover()` marks it
   `failed` with `error = "interrupted"` and the zip is not offered (`GET zip` is 409). Test in Task 12.
5. A face whose bytes equal an existing file under `svf/` **and** whose chosen name differs from that file's: it is
   skipped (not refused), the `LICENCES.tsv.lines` row names the existing path, and `BUILD.md` says so. Test in Task 9.

## Shared data shapes

Every task reads these; later tasks must not rename a key. All paths inside JSON are relative to the job directory
unless the key says `abs`.

**Font entry** (`detect.scan` output, one per detected face; `job["fonts"]` is a list of these):

```json
{"id": "f01", "path": "fonts/NanumGothic-Bold.ttf", "face_index": 0,
 "format": "ttf", "label": "TTF", "source_kind": "outline",
 "family": "NanumGothic", "style": "Bold", "version": "Version 3.00",
 "sizes": [16], "sizes_fixed": false,
 "coverage": {"ascii": 95, "ks2350": 2350, "all": 11172, "compat": 51},
 "jamo": "compat 51/51",
 "dos": null, "bdf": null, "svf": null,
 "licences": [{"path": "fonts/OFL.txt", "first_line": "Copyright (c) ..."}],
 "companions": [], "error": null}
```

- `format` is one of `ttf otf ttc bdf pcf fnt fon hbf dos-raw svf svf1 eng list licence unknown unreadable archive`.
- `source_kind` is one of `outline outline-composite bitmap bdf-iso10646 bdf-iso8859 bdf-ksc5601 bdf-johab hbf
  dos-raw svf-precomposed svf-jamo other` (`bdf-iso8859` is a Latin companion only; `other` for `svf1`, `eng`,
  `list`, `licence`, `unknown`, `unreadable`, `archive`, a BDF of any other registry, and TTC/FON faces with
  `face_index > 0`).
- `jamo` is `"native (<layout>)"` (e.g. `"native (844)"`), `"native (composite)"`, `"native (jset)"`, `"compat N/51"` or `"none"`.
- `dos` is `null` or `{"candidates": ["844", "844-ihnm"], "faces": [0]}` (`faces` is `[0, 1]` for the two Dokkaebi
  printer layouts and the entry is duplicated per face with `face_index` 0 and 1); `bdf` is `null` or
  `{"registry": "iso10646-1", "box": [16, 16]}`; `svf` is `null` or `{"version": 2, "flags": 1, "bpp": 1, "cell": [16, 16], "ascent": 12, "glyphs": 2901}`.
- `companions` lists ids of fonts offered as a Latin companion for this font (`eng` files in the same folder for a DOS
  raw font; ISO10646/ISO8859 BDFs and HBFs anywhere in the batch for a KSC5601 BDF).
- `sizes_fixed` is true for bitmap sources and SVF (only the listed sizes are allowed).

**Settings** (`job["settings"]`):

```json
{"batch": {"dest": "dos", "kinds": ["precomposed"], "layout": "844", "sizes": [16], "bpp": [1, 2], "range": "2350",
           "preset": "plain",
           "options": {"mkfont": {"cell": null, "ascent": null, "mono_hint": false, "clip_cell": false, "space_advance": null},
                       "jamoset": {"embolden": false, "symbols": false}}},
 "fonts": {"f01": {"selected": true, "experimental": false, "dos_layout": null, "latin_companion": null,
                   "licence": {"kind": "upload", "path": "fonts/OFL.txt"},
                   "names": {"precomposed/16/2": "NANUM16X.SVF"},
                   "licence_name": "OFLNANUM.TXT", "note_name": "NANUM.TXT"},
           "f05": {"selected": false, "experimental": false, "dos_layout": null, "latin_companion": "f06",
                   "licence": {"kind": "upload", "path": "dos/LICENSE.txt"}, "names": {},
                   "licence_name": "LICHAN.TXT", "note_name": "HAN.TXT",
                   "kinds": ["jamo"], "dest": "jamo-extra", "bpp": [1]}}}
```

- A per-font dict may carry any `batch` key (`dest kinds layout sizes bpp range preset options`); an absent key
  inherits the batch value, so `detect` stores a batch key per font only when that font's default differs from the
  batch default (f05 above). `selected experimental dos_layout latin_companion licence names licence_name note_name`
  exist per font only and are always present. `licence.kind` is `upload` (`path` relative to `upload/`), `repo`
  (`path` relative to `svf/`, e.g. `dos/OFLNANUM.TXT`) or `text` (`text`). `names` keys are `"<kind>/<size>/<bpp>"`
  and hold only the owner's edits: the effective names are the maker's suggestions for the current selection overlaid
  by this dict (`settings.effective`); a key outside the current selection is ignored.

**Step** (`job["steps"]`, in run order):

```json
{"id": "s01", "font": "f01", "kind": "precomposed", "size": 16, "bpp": 1, "layout": null, "name": "NANUM16.SVF",
 "argv": [["/usr/bin/python3", "-P", "/abs/tools/mkfont.py", "..."]],
 "output": "work/s01/NANUM16.SVF", "state": "pending", "exit": null, "seconds": null, "error": null,
 "stderr_tail": "", "facts": null, "quality": null, "identical_to": null, "preview": null}
```

- `kind` is `precomposed`, `jamo` or `prepare` (a `jamovec master` step; `size`, `bpp`, `name` are `null`, `output` is
  `work/s01/master.json`). `state` is `pending running done failed`. `facts` is `quality.face_facts()`'s dict,
  `quality` is `{"all": 0.93, "ks2350": 0.95, "compared": 2350}` or `null`, `identical_to` an `svf/`-relative path or
  `null`, `preview` `"work/s01/preview.png"` or `null`.

**Job** (`job.json`):

```json
{"id": "3f9c2b7a1d04", "state": "detected", "created": 1760000000.0, "updated": 1760000001.0, "error": null,
 "upload": {"files": 3, "bytes": 123456, "refused": []},
 "fonts": [], "settings": {"batch": {}, "fonts": {}}, "steps": [], "queue_position": null,
 "result": null}
```

- `state` is `uploading detected queued running done failed`; `error` is `null` or a message (`"interrupted"`,
  `"cancelled"`, `"no successful step"`, `"job timeout"`). `result` is `null` or
  `{"zip": "out/<id>.zip", "written": ["svf/dos/NANUM16.SVF"], "skipped": [{"name": "svf/dos/X.SVF", "identical_to": "dos/NEODG16.SVF"}], "failed_steps": ["s03"]}`.

**Files:**

**Interfaces:**

  - `check_rel_path(rel: str) -> str | None`: the reason (`"path has .."`, `"absolute path"`, `"backslash in path"`,
    `"control character in path"`, `"path component over 255 bytes"`, `"empty path"`) or `None`; components are split
    on `/`; `"."` components are refused as `"path has ."`.
  - `kind_of(head: bytes) -> str | None`: `"zip"` (`PK\x03\x04`), `"gzip"` (`\x1f\x8b`), `"xz"` (`\xfd7zXZ\x00`),
    `"tar"` (`ustar` at 257, so `head` must be at least 512 bytes), else `None`.
  - `is_nested_archive(head: bytes, member_bytes_reader) -> bool`: a member is a nested archive when `kind_of(head)`
    is `zip` or `tar`, or is `gzip`/`xz` **and** the first 512 decompressed bytes are a tar header (`ustar` at 257).
    A gzip/xz member with no tar inside (`18x18ko.pcf.gz`, `font.bdf.gz`) is an ordinary file: written as-is, kept
    compressed, and later undone one level by `detect` (Task 3).
  - `unpack(path: str, dest: str, limits=LIMITS) -> dict`: `{"files": n, "bytes": n, "stopped": None | "<reason>"}`.
    The top-level upload: zip via `zipfile`, tar via `tarfile`; a top-level `gzip`/`xz` is opened as tar when the
    decompressed stream starts with a tar header, else written as the single file `dest/<basename without .gz/.xz>`.
    Each member is streamed in 1 MB chunks through a counter; refusals that stop the unpack (`stopped`): a member over
    `member` bytes, total over `total` or over `ratio * packed size`, a member that is not a regular file or
    directory, a member name failing `check_rel_path`, a member that `is_nested_archive`
    (`"nested archive <name> (listed, not opened)"`). What was written before the stop stays. Files land at
    `dest/<member name>`.

## Global Constraints

- Library (`c/src`, `c/include`): C99; only `<stdint.h>`, `<stddef.h>`, `<string.h>`; no `malloc`; data 0 and bss 0 in
  every object (a `static const` table is text); no SIMD, intrinsics or inline asm (the SIMD card t_aa395fa1 comes
  after this plan); `-Werror` on every toolchain.
- **Exact, no fast mode** (user accuracy policy: exact by default; a fast mode may deviate only within bounds, never
  1 bpp output or composition; this card has none). Every change is byte-identical: `make -C c check`,
  `sh c/cross/build-all.sh --ports c/build/cross-ports` (37 OK), every runner's checksums `ok`, the ten
  `c/ports/dos/shots/*.png` unchanged, `make -C c fuzz-smoke` clean after a task that changes how face bytes are read
  (Tasks 6, 8).
- Functions that change: `svf__merge` (svf_jamo.c), the merge branch of `svf__put_rows` (svf_face.c), case 1 of
  `blit_gray8` (svf_draw.c), the area-averaged branch of `svf__scale_cell` (svf_scale.c), one line of
  `svf__glyph_index` (svf_face.c). Public declarations, `svf_chain_scratch_bytes`, the block path and every other blit
  stay as they are.
- `svf__merge(const svf_face *f, uint8_t *dst, uint16_t dst_pitch, const uint8_t *src, uint16_t src_pitch, uint16_t n, uint8_t h)`
  keeps its signature and contract (any run; `src` read like face memory). Face memory is read with plain word loads
  only where `SVF_RD8_PLAIN` is defined or the face is streamed (`SVF__STREAMED(f)`, RAM).
- Word access is `memcpy` of 4 bytes, never a pointer cast; on a strict-align target a word is touched only after a
  run-time test that makes it aligned.
- New `svf.h` switches next to `SVF_WORD_STORE`, `#ifndef` + arch default + `-D` override, each with a comment saying
  what it selects and that the pixels are the same: `SVF_MERGE_WORDS` (default 1, 0 on `__AVR__`) and `SVF_GRAY8_LUT1`
  (default 1, 0 on `__AVR__`).
- Sizes: Cortex-M0+ P1/P2 text <= 8192 (now 6022), written in every library task's commit message (F18). P1* is
  8826 B, accepted by the user (2026-10-23); any growth is reported in the task report and in SIZES.md, and a growth
  over 200 B stops the task for a user ruling. Uno bench flash <= 32,256 (now 27,434). The 8 KB budget does not apply
  to the RP2350, ESP32 or M33 rows.
- The scaler never uses scratch beyond its source cell and its output: the idle second cell between them is poisoned in
  the fuzz builds (`SVF_FUZZ_POISON`, svf_draw.c).
- Runs: absolute OUT paths (`run-dos.sh` refuses a relative one), `vesa-shots.sh` with no argument, `set -o pipefail`
  before `| tee` so an `exit $?` is the runner's (F1, F2). Every number written down says emulated / instructions /
  rp2350js cycles as MEASUREMENTS.md does.
- `make -C c check` green after every task. Commit trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  Stage only the files a task names; never add `.superpowers/`; no `git stash`.

## Review Focus

1. A full-width 1 bpp piece merged into a cell that is **not** 4-aligned (a caller's scratch at an odd address): the
   phase no longer lines source and cell up, the word path must not fire unaligned on a strict-align build, and the
   bytes must be the reference's — Task 6 `test_put_rows` (cell at offsets 0..3, REC 2 / ROW 0 records with phase, a
   build with `-DSVF__MERGE_UNALIGNED=0`).
2. A mapped face under an `SVF_RD8` override (AVR-like, `fuzz-open-rd`, `svfdump-rd8`): the word path must never load
   mapped face bytes with a plain load — Task 6 Step 5 (`make -C c check` TestReadOverride, `make -C c fuzz-smoke`).
3. A 1 bpp GRAY8 cut that starts and ends inside one source byte, a cell left of the target (`x = -3`, `x = -8`) and a
   whole byte ending at the target's last column — Task 7 runs the existing `test_gray8_lut1_cuts` in both the table
   and the `-plain` build.
4. A scaled cell wider than one accumulator block (`sw > 64`: 48 x 48 at 16/3 gives 256) and a last span clamped by
   `cell_w` (47 x 47 at 3/16), with the source cell in exact-size heap memory and the idle scratch poisoned — Task 8
   `test_scale_sweep` and `make -C c fuzz-smoke`.
5. The per-axis weight table at its largest (`num + den - 1` = 31 entries for 16/15 and 15/16): an index past it must be
   an ASan error, not a silent read of the next member — Task 8 keeps the weights in separate local arrays and the
   sweep covers every reduced ratio.

### Task 7: The 1 bpp -> GRAY8 nibble table

**Files:**
- Modify: `c/src/svf_draw.c:520-541` (`blit_gray8` case 1 and the table above `blit_gray8`); `c/include/svf.h` only

**Interfaces:**
- Consumes: `SVF_GRAY8_LUT1` (Task 6), `SVF_WORD_STORE`.
- Produces: under `#if (SVF_TARGETS & SVF_TARGET_GRAY8) && SVF_GRAY8_LUT1`, `static const uint8_t svf__lut1n[16][4]`
  (row `v`: byte `j` is 255 when bit `3 - j` of `v` is set, else 0), written out as 16 literal rows (no macros needed).
  Case 1 of `blit_gray8`: a source byte `v` with `b * 8 >= c0` and `b * 8 + 8 <= c1` (whole inside the cut) ORs row
  `v >> 4` into `dst + x + b * 8` and row `v & 15` into the next 4 bytes: `#if SVF_WORD_STORE` each as one 4-byte
  `memcpy` load, OR, store; else 4 byte ORs each. Partial first and last bytes keep the bit loop; the `!v` skip stays.
  `SVF_GRAY8_LUT1 0`: today's code. INDEXED8 untouched.

**Plan call (deviation from spec section 2):** the spec's 256 x 8 table (2 KB) and this 16 x 4 table do the same work
per source byte (two 4-byte table reads and two 4-byte ORs, or eight byte ORs); the small one adds about 64 B of
rodata where the big one adds 2 KB, which would take the accepted P1* (8826 B) to about 10.9 KB and P3g to about
9.8 KB. AVR keeps 0: a `static const` table without PROGMEM is copied to the Uno's 2 KB of RAM.

### Task 8: The separable box filter

**Files:**
- Modify: `c/src/svf_scale.c:42-85` (`span`, `overlap`, the area-averaged branch of `svf__scale_cell`)
- Test: `c/tests/test_kernels.c` `test_scale_sweep` (exists), `make -C c check` (TestScale), `make -C c fuzz-smoke`

**Interfaces:**
- Consumes: nothing new.
- Produces: `svf__scale_cell` signature, `scale_blocks` (den 1), `svf__scale_len`, `svf__scale_dim` unchanged. New:
  `static unsigned axis_weights(uint8_t num, uint8_t den, uint8_t lo[16], uint8_t cnt[16], uint8_t at[16], uint8_t w[32])`
  returns the number of weights written. For `o` in `0..num-1`: `lo[o] = o * den / num`,
  `cnt[o] = ((o + 1) * den - 1) / num + 1 - lo[o]`, `at[o]` the running sum of the counts before `o`, and
  `w[at[o] + i] = overlap(lo[o] + i, o, num, den)`; the counts of one period sum to at most `num + den - 1 <= 31`.
  Output pixel `q * num + o` covers source pixels `q * den + lo[o] + i`, `i < cnt[o]`, those `< n` (the cell's width or
  height); `q`, `o` are stepped by increment, never divided per pixel. Each axis has its own five locals (separate
  arrays, so ASan sees an index past one).

Algorithm (the order of the integer sums changes, the sums do not: `sum = Σ_sy wy · Σ_sx wx · cov`):
```
for each output row oy (its source rows sy with weights wy from the y tables):
    for each block of at most 64 output columns [ox0, ox1):
        acc[0 .. ox1-ox0) = 0                                  /* uint16_t acc[64]: sum <= 255 * den^2 <= 65280 */
        for each sy of oy's span:
            cov[] = svf__coverage of the source columns the block reads, row sy, once   /* uint8_t cov[255] */
            for ox in block: acc[ox-ox0] += (Σ_i wx_i * cov[sx_i]) * wy
        out[oy * sw + ox] = ((acc << 16) / den2 + 0x8000) >> 16 for ox in block
```
Stack: 2 x (16 + 16 + 16 + 32) + 128 + 255 = 543 B plus scalars; under 640 B (the RP2350 SDK image's 2 KB stack and
the M33 runner's stack hold it). No scratch: the scratch's idle cell is poisoned in fuzz builds.

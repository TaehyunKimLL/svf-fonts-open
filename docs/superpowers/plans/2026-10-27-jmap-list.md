# JMAP-LIST (JSET version 3, flag LIST): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A third mode of the JSET version 3 block, LIST (flag 0x08): a sorted list of at most 255 `u16 key, i, m, f`
entries over the face's one piece pool, its fallback JSET copied verbatim, read by a C reader behind `SVF_JMAP_LIST`
(inside `SVF_JMAP`), written by `jamoset.jmap_list` and a new `tools/jamoexc.py`, with zero bytes in every MCU build.

**Architecture:** Python first (spec text, the `Jmap` list mode and its codec, the `jmap_list` builder, the synthetic
`list*` variants and `jlist_*` bad kinds), because every C test compares against it. Then the C reader in
`c/src/svf_jamo.c` (LIST lookup and L-rules, then the LIST=0 and RECOG fallback-finding arms with the status matrix,
then switch defaults, size budgets and port rows). Then the tool consumers and the exception writer. Then fuzz, the
identity sweep and the records. Four review groups A-D.

**Tech Stack:** C99 (`-Wall -Wextra -Werror`), GNU make, POSIX sh, avr-gcc 16.1.0, arm-none-eabi-gcc 15.2.1, clang
(libFuzzer, ASan), Python 3 (`-I`, unittest), simavr (`c/bench/run-avr.sh`), rp2040js (`c/bench/run-pico.sh`).

**Spec:** `docs/superpowers/specs/2026-10-27-jmap-list-design.md` (r3 at fa76afb, approved by the user 2026-10-27;
"the design"). Its section numbers are cited as §n. Where the design and this plan disagree, the plan's "Plan
rulings" win; a ruling marked **(user)** is one the user should confirm before execution.

Revision r2 folds in three plan reviews of 967d588 (Claude, agy, opencode lanes) and the controller's PL-7 ruling; the

LIST block (from §2; little-endian, byte reads only):

```
off            size    field
0              4       "JSET"
4              u16     version = 3
6              u8      flags: 0x08 LIST; 0x04 FALLBACK; 0x01 (4B) and 0x02 (SPARSE) must be 0 with LIST; bits 4-7 zero
7              u8      advance (px; 0 = cell width); with FALLBACK equal to the fallback's byte 11 (R4)
8              u16     NS, LIST range 1..255 (byte 9 is 0); test: ns - 1u >= 255u on the u16
10             u16 x3  PI, PM, PF: all 0 with LIST
16             u16[51] compat piece numbers (U+3131 + k): 0xFFFF blank, else a pool piece with a glyph
118            NS x 8  entries sorted by key, strictly increasing: u16 key (syllable index s = cp - 0xAC00), u16 i, m, f
F = 118 + 8NS  rest    FALLBACK only: a JSET version 1 or 2 block to the region end; F <= 2,158
```

- Fields are piece numbers (glyph U+F0000 + n); 0xFFFF blank; piece 0 is a piece. A hit returns `[i, m, f]` when `f !=
  0xFFFF`, else `[i, m]`. The fallback is not shifted and shares the pool.
- Rules, in order: **R1'** length >= 118, magic, version 3, `flags & 0xF0 == 0`, not `(fl & 8) && (fl & 3)`; **L2** PI =
  PM = PF = 0; **L3** NS 1..255; **R4** region <= 65,534, without FALLBACK length == F, with it length >= F + 12, fallback
  magic, version 1 or 2, advance byte equal, then the fallback's own validity; **L5** compat 0xFFFF or a glyph;
  **L6** keys strictly increasing and the last <= 11,171; **L7** every field 0xFFFF or a glyph. Header rules R1', L2,
  L3, R4; content rules L5-L7 (skipped under `SVF_JSET_TRUSTED`). Python `unpack_jmap` raises `JMAP R1`, `JMAP L2`,
  `JMAP L3`, `JMAP R4`, `JMAP L6`; L5 and L7 are `parse_svfn`'s usable rule.
- Sizes: `118 + 8 NS (+ fallback)`; NS 36 -> 406; NS 255 -> 2,158; SPARSE 3B at 255 -> 2,369.
- Statuses (no new bit): `SVF_JMAP=1 SVF_JMAP_LIST=1` reads it (any rule fails: `JMAP_BAD`, plain);
  `SVF_JMAP=1 SVF_JMAP_LIST=0` applies the header rules only (fail: `JMAP_BAD`; pass: `JMAP_UNREAD`, fallback used);
  `SVF_JMAP=0 SVF_JMAP_RECOG=1` keeps the recognition's rule set (§4 table); neither: `JSET_BAD`.

  `check_absent ... jlist` relies on this and is only meaningful if a `jlist_` symbol survives `-Os` (Task 7 records it).
- **PL-3 No new `svfdump info` key** (§10 item 4 "`svfdump info` fields": none is needed). Where a listed syllable comes

  kind raises the rule named in Task 4's table.

  the source cmap (0 if none), syllables in ascending s first, then compat jamo in ascending k. A new number reaching
  0xFFFF (= BLANK) is refused: `"jmap_list: no free piece number above U+F{top:04X}"`.

## Review Focus

1. **A LIST face on an image that does not read LIST** (`SVF_JMAP_LIST=0`, or RECOG): Hangul still composes from the
   fallback; a block with unsorted keys or a field without a glyph composes there although a LIST=1 build refuses it.
   Task 6 `test_jmap_list_status_matrix` pins every kind x build.
2. **Piece 0 and the 0xFFFE edge**: an entry naming piece 0 draws it (never blank); a field of 0xFFFE without a glyph is
   `JMAP_BAD`. Task 2 `test_list_piece_zero`, Task 5 `test_jmap_list_compose` (`list_zero`), Task 6 matrix
   (`jlist_field_fffe`).
3. **A version change renumbering the fallback under the entries**: `--jset-version 2` on a version 1 source with
   non-canonical numbers must compose identically. Task 3 `test_jmap_list_reencode_keeps_numbers`, Task 4 `list2`,
   Task 9 `test_jset_version_reencode`.
4. **Binary search edges**: first key 0, last key 11,171, NS = 1, NS = 255, the syllables either side of each key.
   Task 4 (`list_max`, `list_nofb` shapes), Task 5 `test_jmap_list_search_edges`.
5. **An exception face that silently loses what the source drew**: a whole glyph equal to the fallback's composition
   (hides a reader that ignores the LIST; Task 4 `test_list_variants_distinguishable`), a source with a non-zero JSET
   advance (Task 3 `test_jmap_list_advance`), and `jamoexc` dropping metrics, layout or the fallback version (Task 9
   `test_build_fidelity`).
